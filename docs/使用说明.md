## 1. 项目介绍

**xingye-kit（星叶工具箱）** 是一套面向日常开发的通用 Java 工具集，按功能拆分为 11 个 Maven 模块：

| 模块 | 一句话定位 |
|---|---|
| `xingye-kit-core` | 统一返回、业务异常、断言、字符串/日期工具、重试模板 |
| `xingye-kit-id` | 雪花 ID、UUID、短码、请求流水号 |
| `xingye-kit-net` | 轻量 HTTP 客户端、限流器（令牌桶/漏桶）、熔断器（滑动窗口/并发信号量） |
| `xingye-kit-notify` | 短信/邮件/Webhook 通知接口、验证码、通知模板 |
| `xingye-kit-io` | 文件、ZIP、CSV、二维码、图片工具 |
| `xingye-kit-cache` | 本地缓存、Redis 辅助、幂等工具 |
| `xingye-kit-cache-redis` | Redis 真实适配：基于 Jedis 连接池实现 `RedisClient` |
| `xingye-kit-security` | AES/RSA 加解密、哈希、JWT、日志脱敏 |
| `xingye-kit-boot` | Spring Boot 自动装配（唯一依赖 Spring 的模块） |
| `xingye-kit-sms-aliyun` | 阿里云短信适配：真实发送模板短信（实现 `SmsClient`） |
| `xingye-kit-mail` | 邮件适配：SMTP 真实发送文本/HTML/附件（实现 `MailClient`） |

三条设计原则，使用前建议了解：

1. **零依赖**：除 `boot` 外的 7 个核心模块只依赖 JDK，不含任何第三方库；
2. **JDK 8 兼容**：源码锁定 JDK 8 语法、编译为 JDK 8 字节码，可在 JDK 8/11/17/21/25 上直接运行；
3. **接口与实现分离**：涉及外部厂商的能力（短信、邮件、Redis）只定义接口并提供内存/日志版默认实现；`sms-aliyun` / `mail` / `cache-redis` 三个适配模块提供真实厂商实现（各自引入厂商 SDK），不强绑进核心模块。

## 3. 安装步骤

### 3.1 方式一：JitPack 在线引入（推荐，免克隆源码）

第一步，在 `pom.xml` 中添加 JitPack 仓库：

```xml
<repositories>
    <repository>
        <id>jitpack.io</id>
        <url>https://jitpack.io</url>
    </repository>
</repositories>
```

第二步，按需添加依赖。引入全部模块（JitPack 自动生成聚合坐标）：

```xml
<dependency>
    <groupId>com.github.RainxButterfly</groupId>
    <artifactId>xingye-kit</artifactId>
    <version>v1.0.0</version>
</dependency>
```

或者只引入单个模块（groupId 规则：`com.github.用户名.仓库名`）：

```xml
<dependency>
    <groupId>com.github.RainxButterfly.xingye-kit</groupId>
    <artifactId>xingye-kit-core</artifactId>
    <version>v1.0.0</version>
</dependency>
```

说明：版本号对应 GitHub Tag（先打 tag 如 `v1.0.0`，首次引入时 JitPack 自动构建约 1~2 分钟）；聚合坐标引入的 11 个模块中，`boot` 的 Spring 依赖为 `provided`，不会传递引入；`sms-aliyun` 的阿里云 SDK、`mail` 的 JavaMail 与 `cache-redis` 的 Jedis 仅在引入对应适配模块时才会传递进来；JitPack 默认以 OpenJDK 8 构建，与本工程 `source/target=1.8` 兼容。

### 3.2 方式二：源码构建安装到本地仓库

```bash
git clone https://github.com/RainxButterfly/xingye-kit.git
cd xingye-kit
mvn clean install
```

构建成功后，11 个模块的 jar 会安装到本地 Maven 仓库（`~/.m2/repository/com/xingheyiye/`）。

### 3.3 方式三：项目中直接引入依赖

按需引入对应模块（各核心模块可独立使用；`xingye-kit-id` 依赖 `core`，其余模块零内部依赖）：

```xml
<dependency>
    <groupId>com.xingheyiye</groupId>
    <artifactId>xingye-kit-core</artifactId>
    <version>1.0.0</version>
</dependency>
```

把 `artifactId` 换成你需要的模块名即可，例如 `xingye-kit-net`、`xingye-kit-security`。

### 3.4 方式四：Spring Boot 项目（自动装配）

```xml
<dependency>
    <groupId>com.xingheyiye</groupId>
    <artifactId>xingye-kit-boot</artifactId>
    <version>1.0.0</version>
</dependency>
```

引入后无需任何注解，自动注册 `HttpTool`、`Snowflake`/`IdGenerator`、`LocalCache`、`Notifier` 等 Bean，详见 5.8 节。

### 3.5 验证安装是否成功

在任意类中执行以下代码，能正常输出即安装成功：

```java
import com.xingheyiye.xingye.kit.core.Result;

public class InstallCheck {
    public static void main(String[] args) {
        System.out.println(Result.ok("hello xingye-kit"));
        // 输出形如：Result{code=200, message='success', data=hello xingye-kit}
    }
}
```

## 4. 快速上手

```java
Result<User> result = Result.ok(user);
```

```java
@Autowired

```

## 5. 核心功能详解

> 约定：下文所有类名的 import 前缀均为 `com.xingheyiye.xingye.kit.`，例如
> `com.xingheyiye.xingye.kit.core.Result`。为节省篇幅，示例代码省略 import。

### 5.1 xingye-kit-core 基础核心

#### 5.1.1 Result\<T\> —— 统一返回结果

| 方法 | 参数说明 | 返回值 |
|---|---|---|
| `static <T> Result<T> ok()` | 无 | code=200、无数据的成功结果 |
| `static <T> Result<T> ok(T data)` | data：业务数据，可为 null | 携带数据的成功结果 |
| `static <T> Result<T> fail(int code, String message)` | code：业务错误码；message：错误描述 | 失败结果 |
| `static <T> Result<T> fail(ErrorCode errorCode)` | errorCode：错误码枚举 | 失败结果 |
| `int getCode()` | - | 状态码（200 成功，见常量 `CODE_SUCCESS`/`CODE_FAIL`） |
| `String getMessage()` | - | 描述信息 |
| `T getData()` | - | 业务数据，未设置时为 null |
| `boolean isSuccess()` / `isFail()` | - | 是否成功 / 是否失败 |

```java
Result<User> ok = Result.ok(user);
if (ok.isSuccess()) {
    User data = ok.getData();
}

Result<Void> notFound = Result.fail(40401, "订单不存在");
```

#### 5.1.2 ErrorCode / BizException —— 错误码与业务异常

`ErrorCode` 是接口，只需两个方法：`int getCode()` 与 `String getMessage()`，推荐用业务枚举实现：

```java
public enum OrderErrorCode implements ErrorCode {
    NOT_FOUND(40401, "订单不存在"),
    SOLD_OUT(40902, "库存不足");

    private final int code;
    private final String message;

    OrderErrorCode(int code, String message) {
        this.code = code;
        this.message = message;
    }

    public int getCode() { return code; }
    public String getMessage() { return message; }
}
```

`BizException` 携带错误码的运行时异常，常用构造器：

| 构造器 | 说明 |
|---|---|
| `BizException(String message)` | 仅描述 |
| `BizException(int code, String message)` | 错误码 + 描述 |
| `BizException(int code, String message, Throwable cause)` | 需要保留底层异常时 |
| `BizException(ErrorCode errorCode)` | 由枚举构造 |
| `BizException(ErrorCode errorCode, Throwable cause)` | 枚举 + 底层异常 |

读取错误码：`exception.getCode()`。

#### 5.1.3 Assert —— 参数断言

校验失败抛出 `BizException(code, message)`，全部为静态方法：

| 方法 | 校验内容 |
|---|---|
| `isTrue(boolean expression, int code, String message)` | 表达式必须为 true |
| `notNull(Object object, int code, String message)` | 对象非 null |
| `notEmpty(String text, int code, String message)` | 字符串非空串 |
| `notEmpty(Collection<?> c, int code, String message)` | 集合非空 |
| `notEmpty(Map<?,?> map, int code, String message)` | Map 非空 |
| `notEmpty(Object[] array, int code, String message)` | 数组非空 |

```java
Assert.notNull(order, OrderErrorCode.NOT_FOUND.getCode(), OrderErrorCode.NOT_FOUND.getMessage());
```

#### 5.1.4 StringUtils —— 字符串工具（全部 null 安全、静态方法）

| 方法 | 参数说明 | 返回值 |
|---|---|---|
| `isEmpty(String)` / `isNotEmpty(String)` | - | 是否为 null 或空串 |
| `isBlank(String)` / `isNotBlank(String)` | - | 是否为 null/空串/纯空白 |
| `maskPhone(String phone)` | 11 位手机号 | `138****5678`；长度不足时全 `*` |
| `maskIdCard(String idCard)` | 身份证号 | 前 3 后 4，如 `330***********1234` |
| `maskEmail(String email)` | 邮箱 | `a***@domain.com` |
| `maskName(String name)` | 中文姓名 | `张**` |
| `maskBankCard(String card)` | 银行卡号 | 前 4 后 4 |
| `camelToUnderline(String text)` | 驼峰串 | 下划线串，如 `userName` → `user_name` |
| `underlineToCamel(String text)` | 下划线串 | 驼峰串 |
| `format(String template, Map<String,?> params)` | 模板含 `${key}` 占位 | 替换结果；缺失的占位符保留原样 |
| `format(String template, Object... args)` | 模板含 `{}` 顺序占位 | 按顺序替换结果 |
| `repeat(String text, int count)` | - | 重复拼接后的串 |

```java
StringUtils.maskPhone("13800138000");      // 138****8000
StringUtils.format("用户{}下单{}", "张三", 1001);   // 用户张三下单1001
```

#### 5.1.5 DateUtils —— 日期时间工具（全部静态方法、线程安全）

| 方法 | 参数说明 | 返回值 |
|---|---|---|
| `now()` | - | 当前 `LocalDateTime` |
| `format(LocalDateTime time, String pattern)` | pattern 如 `yyyy-MM-dd HH:mm:ss`（常量 `PATTERN_DATETIME`） | 格式化字符串 |
| `formatNow(String pattern)` | - | 当前时间格式化串 |
| `parse(String text, String pattern)` | - | `LocalDateTime`；格式不符抛 `DateTimeParseException` |
| `toDate(LocalDateTime time)` / `toLocalDateTime(Date date)` | - | 新旧日期 API 互转（默认系统时区，均有带 `ZoneId` 的重载） |
| `beginOfMonth(LocalDateTime time)` | - | 当月第一天 00:00:00 |
| `endOfMonth(LocalDateTime time)` | - | 当月最后一天 23:59:59.999999999 |
| `relativeTime(LocalDateTime time)` | - | 相对时间：`3分钟前`、`2小时后`；超过 30 天回退为 `yyyy-MM-dd` 格式 |

```java
DateUtils.format(DateUtils.now(), DateUtils.PATTERN_DATETIME);
DateUtils.relativeTime(order.getCreatedAt());   // 例如 "5分钟前"
```

#### 5.1.6 StopWatch —— 耗时统计

| 方法 | 返回值 |
|---|---|
| `start()` / `stop()` | 自身（可链式）；未 start 就 stop 抛 `IllegalStateException`；可多次 start/stop 累计 |
| `elapsedMillis()` | **double**，累计耗时（毫秒） |
| `pretty()` | 可读串，如 `123.4 ms` 或 `1.234 s` |

```java
StopWatch watch = new StopWatch().start();
doSomething();
watch.stop();
System.out.println(watch.pretty());
```

#### 5.1.7 RetryTemplate —— 重试模板（构建后不可变、线程安全）

| 方法 | 参数说明 | 返回值 |
|---|---|---|
| `static RetryTemplate create()` | - | 新实例（默认最多 3 次、不限定异常类型） |
| `maxAttempts(int maxAttempts)` | 总尝试次数上限，≥1 | 新配置实例 |
| `retryOn(Class<? extends Throwable>... types)` | 只有命中这些异常才重试 | 新配置实例 |
| `backoff(long millis)` | 固定间隔（毫秒） | 新配置实例 |
| `exponentialBackoff(long initialMillis, double multiplier, long maxMillis)` | 初始间隔、倍率、间隔上限 | 新配置实例 |
| `<T> T execute(Supplier<T> action)` | 业务逻辑（Lambda） | 成功结果；重试耗尽抛最后一次异常（受检异常包成 RuntimeException） |
| `void execute(Runnable action)` | 无返回值版本 | - |

```java
String data = RetryTemplate.create()
        .maxAttempts(3)
        .retryOn(IOException.class)
        .exponentialBackoff(200, 2.0, 2000)
        .execute(() -> loadFromRemote());
```

### 5.2 xingye-kit-id 标识生成

#### 5.2.1 Snowflake —— 雪花 ID（线程安全，synchronized 发号）

| 方法 | 参数说明 | 返回值 |
|---|---|---|
| `new Snowflake(long workerId, long datacenterId)` | 默认布局 5 位数据中心 + 5 位机器 + 12 位序列，取值均 0..31 | - |
| `new Snowflake(workerId, datacenterId, datacenterIdBits, workerIdBits, sequenceBits, maxBackwardsMillis)` | 自定义位分配（三段位数之和 ≤22）与时钟回拨容忍毫秒数（默认 5） | - |
| `synchronized long nextLongId()` | - | 64 位趋势递增 ID |
| `String nextId()` | `IdGenerator` 接口实现 | ID 的字符串形式 |
| `long extractTimestamp(long id)` | - | 反解该 ID 的生成时刻（毫秒时间戳） |
| `long extractWorkerId(long id)` / `extractDatacenterId(long id)` | - | 反解机器位/数据中心位 |

**重要约定：**

- 起始纪元 `TW_EPOCH = 1735689600000L`（2025-01-01 UTC），ID 可用年限与该纪元相关；
- 时钟回拨在 `maxBackwardsMillis` 内自动自旋等待，超出抛 `IllegalStateException`（消息含回拨毫秒数）；
- **多实例部署时必须为每个实例分配不同的 workerId**，否则会发重号。

```java
Snowflake snowflake = new Snowflake(1, 1);
long id = snowflake.nextLongId();
long bornAt = snowflake.extractTimestamp(id);   // 注意：实例方法
```

#### 5.2.2 UuidUtils —— UUID（静态方法）

| 方法 | 说明 |
|---|---|
| `random()` | 标准 36 位带横杠 |
| `simple()` | 32 位无横杠 |
| `fast()` | 基于 ThreadLocalRandom 的高性能版，**非加密安全**，仅用于低碰撞要求的内部场景 |
| `ordered()` | 12 位时间戳十六进制前缀 + 20 位随机，趋势有序，适合做 MySQL 主键 |

#### 5.2.3 ShortCode —— Base62 短码（静态方法）

| 方法 | 参数说明 | 返回值 |
|---|---|---|
| `encode(long id)` | 非负整数 | Base62 短码；负数抛 `IllegalArgumentException` |
| `decode(String code)` | 短码 | 原 long 值；非法字符抛 `IllegalArgumentException` |
| `random(int length)` | 长度 1..32 | SecureRandom 随机短码 |
| `randomUnambiguous(int length)` | 长度 1..32 | 使用剔除 `0/O/1/l/I` 的防歧义字符表 |

#### 5.2.4 RequestNo —— 请求流水号（Builder，线程安全）

```java
RequestNo requestNo = RequestNo.builder()
        .node("07")                    // 节点标识，默认 "00"
        .seqLength(4)                  // 序列位数 1..6，默认 4
        .timestampPattern("yyMMddHHmmssSSS")   // 时间格式，默认到毫秒
        .build();

String no = requestNo.next();   // 形如 260830101530123070001（时间+节点+序列，序列回绕自动补零）
```

### 5.3 xingye-kit-net HTTP 与远程调用

#### 5.3.1 HttpRequest —— 请求构建（Builder，不可变对象）

入口工厂：`HttpRequest.get(url)` / `post(url)` / `put(url)` / `delete(url)` / `head(url)`。

| 链式方法 | 参数说明 |
|---|---|
| `query(String name, String value)` | 追加查询参数（UTF-8 自动编码，可多次调用） |
| `header(String name, String value)` / `headers(Map<String,String>)` | 请求头 |
| `body(String body)` / `body(byte[] body, String contentType)` | 原始请求体 |
| `json(String json)` | JSON 请求体（自动设置 Content-Type） |
| `form(Map<String,String> fields)` | 表单（x-www-form-urlencoded） |
| `file(String fieldName, File file)` | multipart 文件上传，可多个、可与 form 混用 |
| `connectTimeoutMillis(int)` / `readTimeoutMillis(int)` | 覆盖单次请求的超时 |
| `maxRetry(int)` | 覆盖单次请求的重试次数 |
| `proxy(String host, int port)` | HTTP 代理 |
| `basicAuth(String user, String pass)` / `bearerToken(String token)` | 认证头 |
| `traceId(String traceId)` | 链路追踪 ID（写入 `X-Trace-Id` 头；不设则自动生成） |
| `build()` | 生成不可变请求对象 |

#### 5.3.2 HttpTool —— 执行器（网络错误不抛异常，而是返回带错误类型的响应）

| 方法 | 说明 |
|---|---|
| `static HttpResponse send(HttpRequest request)` | 静态便捷入口（默认超时 5s/10s、不重试） |
| `new HttpTool()` | 使用默认配置的实例 |
| `new HttpTool(int connectTimeoutMillis, int readTimeoutMillis, int maxRetry)` | 自定义配置；请求未单独设置时生效 |
| `HttpResponse execute(HttpRequest request)` | 实例执行方法 |

内置能力：手动重定向（最多 5 次）、gzip 自动解压、指数退避重试（仅连接类错误）、multipart 组装、耗时统计（nanoTime）。
**注意：响应体会全量读入内存，不适合下载超大文件。**

`HttpClient` 接口的第二个内置实现为 `StubHttpClient`（联调桩，见 5.3.6）：不发起真实网络请求，按预设响应返回并记录请求历史，适合单元测试与本地联调。

#### 5.3.3 HttpResponse —— 响应对象（不可变）

| 方法 | 返回值 |
|---|---|

#### 5.3.5 CircuitBreaker —— 熔断器（滑动窗口 / 并发信号量）

```java
// 内置选择一：滑动窗口失败率熔断
// name, 滑动窗口 20 次, 失败率阈值 0.5, OPEN 冷却 30s, 半开放行 1 个试探请求
CircuitBreaker breaker = new SlidingWindowCircuitBreaker("order-query", 20, 0.5, 30000L, 1L);

if (breaker.allowRequest()) {
    try {
        callRemote();
        breaker.recordSuccess();      // HALF_OPEN 下全部成功将回到 CLOSED
    } catch (Exception e) {
        breaker.recordFailure();      // 窗口内失败率达标则跳 OPEN
    }
}
System.out.println(breaker.getState());   // CLOSED / OPEN / HALF_OPEN

// 内置选择二：并发信号量熔断，在途最多 50 个并发请求，超限快速失败（不统计成败）
CircuitBreaker concurrency = new ConcurrencyLimitCircuitBreaker("pay-service", 50);
if (concurrency.allowRequest()) {
    try { callRemote(); concurrency.recordSuccess(); }   // 占用许可后无论成败都必须 record 归还
    catch (Exception e) { concurrency.recordFailure(); }
}

// 自定义熔断策略：实现 CircuitBreaker 接口（allowRequest / recordSuccess / recordFailure /
// getState / reset），可包装 Resilience4j、Hystrix 等
```

| 方法 | 返回值 |
|---|---|
| `allowRequest()` | 当前是否放行（OPEN 态冷却期满进入 HALF_OPEN 放行试探） |
| `recordSuccess()` / `recordFailure()` | void，记录一次调用结果 |
| `getState()` | 当前状态 |
| `reset()` | 清零统计回到 CLOSED |

### 5.6 xingye-kit-cache 缓存

#### 5.6.1 LocalCache —— 本地缓存（TTL + 近似 LRU + 后台定时清理，线程安全）

```java

        .expireAfterWriteMillis(60000)    // 写入后 60s 过期，默认 1 小时
```

**Redisson 适配**（放你的工程，约 40 行完成接入）。关键点：`RBucket` 必须显式传 `StringCodec.INSTANCE`，否则 Redisson 默认 Jackson 二进制编码会与其他客户端/redis-cli 互读失败：

```java
public class RedissonRedisClient implements RedisClient {

    private final RedissonClient redisson;

    public RedissonRedisClient(RedissonClient redisson) {
        this.redisson = redisson;
    }

    @Override
    public String get(String key) {
        return redisson.getBucket(key, StringCodec.INSTANCE).get();
    }

    @Override
    public String set(String key, String value) {
        redisson.getBucket(key, StringCodec.INSTANCE).set(value);
        return "OK";   // Redisson 的 set 无命令回复，按接口契约返回 "OK" 表示成功
    }

    @Override
    public boolean setNx(String key, String value, long expireMillis) {
        // trySet(value, Duration) 等价原子的 SET key value NX PX millis
        return redisson.getBucket(key, StringCodec.INSTANCE)
                .trySet(value, Duration.ofMillis(expireMillis));
    }

    @Override
    public long incr(String key) {
        return redisson.getAtomicLong(key).incrementAndGet();
    }

    @Override
    public boolean expire(String key, long millis) {
        // Redisson 3.12+ 为 expire(Duration)；更老版本改用 expire(millis, TimeUnit.MILLISECONDS)
        return redisson.getBucket(key, StringCodec.INSTANCE).expire(Duration.ofMillis(millis));
    }

    @Override
    public boolean del(String key) {
        return redisson.getBucket(key, StringCodec.INSTANCE).delete();
    }
}
```

Spring Boot 装配（boot 模块不自动装配 Redis 侧，需手动声明两个 Bean）：

```java
}
```

> 选型建议：已在用 Redisson 时，分布式锁建议直接用其原生 `RLock`（可重入、看门狗自动续期）；`RedisHelper` 在此组合下更适合 key 前缀管理与窗口计数，两者可并存。

`RedisHelper` 提供三件常用事：

```java
RedisHelper redis = new RedisHelper(jedisClient, "app1");

String k = redis.key("user", "1001");          // app1:user:1001（统一前缀拼接）

if (redis.tryLock("order:1001", "worker-07", 30000L)) {
    try {
        // 临界区
    } finally {
        redis.unlock("order:1001", "worker-07");   // 只有持锁者能解
    }
}

long times = redis.nextCount("api:/pay", 60000L);   // 60s 固定窗口计数（窗口内自增）
```

| 方法 | 参数说明 | 返回值 |
|---|---|---|
| `key(String... parts)` | 各段非空 | 冒号拼接的完整 key |
| `tryLock(String name, String holder, long leaseMillis)` | holder：持锁者标识 | 是否抢到锁 |
| `unlock(String name, String holder)` | - | 是否成功释放（holder 不匹配则 false） |
| `nextCount(String name, long windowMillis)` | - | 当前窗口内第几次 |

#### 5.6.3 Idempotent —— 幂等去重

```java
Idempotent idempotent = new Idempotent(new MemoryIdempotentStore());   // 单机内存版
// 分布式场景：new Idempotent(new RedisIdempotentStore(redis, "idem"))，见 5.4.7

if (!idempotent.tryBegin(requestNo, 30000L)) {   // false 表示 30s 内重复请求
    return Result.fail(40901, "重复请求，请勿重复提交");
}
try {
    doBusiness();
    idempotent.complete(requestNo);   // 业务成功，清除标记
} catch (Exception e) {
    idempotent.cancel(requestNo);     // 业务失败，允许重试
    throw e;
}
```

### 5.7 xingye-kit-security 安全

> 以下工具方法多数声明 `throws GeneralSecurityException`，属受检异常，调用处需处理。

#### 5.7.1 AESUtils —— AES-GCM 加解密

| 方法 | 说明 |
|---|---|
| `generateKey(int bits)` | 生成密钥，bits ∈ 128/192/256 |
| `encryptToBase64(SecretKey, String plain)` | 加密；随机 12 字节 IV 前置后整体 Base64 |
| `decryptFromBase64(SecretKey, String cipherBase64)` | 解密 |
| `randomSalt(int bytes)` | 生成随机盐 |
| `deriveKey(String password, byte[] salt)` | 口令派生密钥（PBKDF2，默认 210000 次迭代、128 位，另有四参重载可调） |
| `encryptWithPassword(String password, String plain)` | 便捷方法：内部随机盐+派生密钥，输出 `salt(16B) + iv(12B) + 密文` 的 Base64 |
| `decryptWithPassword(String password, String cipherBase64)` | 配套解密；口令错误抛 `AEADBadTagException` |

```java
String cipher = AESUtils.encryptWithPassword(password, "机密数据");
String plain = AESUtils.decryptWithPassword(password, cipher);
```

#### 5.7.2 RSAUtils —— RSA 加解密与签名

| 方法 | 说明 |
|---|---|
| `generateKeyPair()` / `generateKeyPair(int keySize)` | 生成密钥对（默认 2048；小于 2048 拒绝并提示不安全） |
| `toBase64(PublicKey/PrivateKey)` / `parsePublicKey/parsePrivateKey(String)` | 密钥与 Base64 互转（X509/PKCS8） |
| `encrypt(PublicKey, byte[] plain)` | OAEP-SHA256 加密；明文超过 keySize/8-66 字节抛异常（提示改用混合加密） |
| `decrypt(PrivateKey, byte[] cipher)` | 分块解密 |
| `signBase64(PrivateKey, byte[] data)` | SHA256withRSA 签名，返回 Base64 |
| `verify(PublicKey, byte[] data, String signBase64)` | 验签；返回 false 不抛异常 |

#### 5.7.3 HashUtils / PasswordHasher —— 哈希与密码

```java
HashUtils.sha256Hex("abc");                       // SHA-256 十六进制
HashUtils.hmacSha256Hex(secret, data);            // HMAC-SHA256
HashUtils.randomSaltHex(16);                      // 随机盐
HashUtils.constantTimeEquals(a, b);               // 常量时间比较（防时序攻击）

// 密码哈希：PBKDF2（内置实现），同密码每次 hash 结果不同，verify 必须配对使用
PasswordHasher hasher = new Pbkdf2PasswordHasher();          // 默认 210000 次 / 256 位
// 也可 new Pbkdf2PasswordHasher(iterationCount, keyLengthBits, algorithm) 自定义
String stored = hasher.hash("raw-password");                 // pbkdf2-sha256$210000$盐$哈希
boolean ok = hasher.verify("raw-password", stored);          // 格式不符抛 IllegalArgumentException
```

BCrypt / Argon2：实现 `PasswordHasher` 接口（`hash` / `verify` 两个方法）包装第三方库即可接入。

#### 5.7.4 JwtWrapper —— 零依赖 JWT（HS256/384/512、RS256）

```java
// 生成
String token = JwtWrapper.create()
        .issuer("app1")
        .subject("login")
        .claim("uid", 10001L)          // 任意声明
        .expiresInSeconds(1800)        // 30 分钟后过期（另有 expirationMillis/notBeforeMillis 等）
        .signHmacSha256("at-least-16-bytes-secret");   // secret 至少 16 字节，否则抛 IllegalArgumentException

// 校验并取声明（签名不符/过期/未生效均抛 JwtException，消息语义化）
JwtClaims claims = JwtWrapper.verify(token, "at-least-16-bytes-secret");
Long uid = claims.getLongClaim("uid");
String issuer = claims.getStringClaim("iss");

// RS256 非对称：signRsa(PrivateKey) 生成，verify(token, PublicKey) 校验
```

安全提示：secret 务必从配置/环境变量注入；本实现拒绝 `alg=none`，HMAC 比较使用常量时间。

#### 5.7.5 Sensitive / SensitiveMask —— 日志脱敏

```java
public class UserVO {
    @Sensitive(SensitiveType.PHONE)     private String phone;
    @Sensitive(SensitiveType.ID_CARD)   private String idCard;
    @Sensitive(SensitiveType.BANK_CARD) private String bankCard;
}

UserVO vo = new UserVO();
SensitiveMask.maskObject(vo);                 // 反射回写脱敏值（含父类字段）
String s = SensitiveMask.mask("13800138000", SensitiveType.PHONE);   // 手工脱敏
```

`SensitiveType` 取值：`PHONE` / `ID_CARD` / `EMAIL` / `NAME` / `BANK_CARD` / `ADDRESS`（保留前 6 后 4，不足全 `*`）。
注意 `maskObject` 会**原地修改**传入对象，打印日志前对副本调用更安全。

## 6. 常见问题解答（FAQ）

**Q1：最低能用 JDK 几？高版本 JDK 有问题吗？**
JDK 8 及以上均可。字节码编译目标为 1.8，JDK 8/11/17/21/25 向下兼容直接运行。

**Q2：我不是 Spring Boot 项目，能用吗？**
可以。除 `xingye-kit-boot` 外的 7 个核心模块均为纯 Java 零依赖，任何 Java 项目（含 Android 服务端、纯工具程序）都能用；`sms-aliyun` / `mail` / `cache-redis` 三个适配模块仅额外引入各自厂商 SDK，同样不依赖 Spring。

**Q3：Spring Boot 3.x 项目能引入 xingye-kit-boot 吗？**
可以。自动装配使用 2.7/3.x 双注册文件与双版本通用的注解写法；`spring-boot-autoconfigure` 以 `provided` 方式由宿主应用提供。

**Q4：多台服务器部署，雪花 ID 会重复吗？**
会，如果 workerId 相同。请为每个实例配置不同的 `xingye-kit.id.worker-id`（0..31）；需要更多实例可改用全参构造器调整位分配。

**Q5：服务器时间被回拨了会怎样？**
回拨幅度 ≤ maxBackwardsMillis（默认 5ms）时自旋等待自愈；超出抛 `IllegalStateException` 并在消息中给出回拨毫秒数，此时应排查 NTP 或等待时间追上。

**Q6：HttpTool 为什么网络错误不抛异常？**
设计取舍：错误也以 `HttpResponse` 返回（`getErrorType()` 分类），调用方可用统一分支处理"成功/超时/连接失败"，避免 try-catch 嵌套。判断成功用 `isSuccess()`。

**Q7：调用 QrCodeUtils 报 IllegalStateException？**
说明类路径没有 ZXing。二维码为可选能力，按 5.5.4 节在你的项目中引入 `com.google.zxing:core` 与 `javase` 即可，其余功能不受影响。

**Q8：RedisHelper 怎么连 Redis？支持 Redisson 吗？**
本模块不内置 Redis 客户端。实现 `RedisClient` 的 6 个方法（get/set/setNx/incr/expire/del），把你现有的 Jedis/Lettuce/Redisson 委托进去，再传入 `RedisHelper` 即可。Redisson 完整适配示例见 5.6.2 节；要点：RBucket 用 `StringCodec.INSTANCE`、incr 用 `RAtomicLong.incrementAndGet()`、setNx 用 `trySet(value, Duration)` 保证原子（需 Redisson 3.12+）。已在用 Redisson 时，锁场景建议直接用其原生 `RLock`（可重入 + 看门狗续期），`RedisHelper` 更适合 key 前缀与窗口计数。

**Q9：密码哈希为什么没有 BCrypt/Argon2？**
核心模块零依赖原则下，内置了 PBKDF2（OWASP 推荐参数）。需要 BCrypt/Argon2 时实现 `PasswordHasher` 接口包装对应第三方库，业务代码面向接口不变。

**Q10：本地缓存重启后数据还在吗？**
不在。`LocalCache` 是进程内缓存，重启即清空；需要持久化或分布式缓存请接入 Redis 方案。`InMemoryCodeStore`、`MemoryIdempotentStore` 同理，分布式场景请引入 `xingye-kit-cache-redis`，用内置 `RedisCodeStore`、`RedisIdempotentStore`（内部走 `JedisRedisClient`），见 5.4.7；使用其他客户端（Lettuce/Redisson）时实现对应接口即可。

**Q11：AGPLv3.0 协议对我商用有什么影响？**
你可以自由使用、修改、分发；但若修改了本库并通过网络对外提供服务，需要开源你的修改部分。仅作为依赖使用（未修改源码）一般不受额外约束，具体请阅读仓库 `LICENSE` 或咨询法务。

**Q12：编译时报"非法的 Unicode 转义"？**
常见于在注释里写了 `\uXXXX` 字样（javac 会对注释中的该序列做 Unicode 预处理）。避免在注释里出现反斜杠+u 的字面写法即可。

### 7.2 线程安全速查

| 类 | 线程安全 | 说明 |
|---|---|---|
| Result / StringUtils / DateUtils / HashUtils / AESUtils / RSAUtils / FileUtils / ZipUtils | 安全 | 不可变对象或纯静态无状态 |
| Snowflake / RequestNo / RateLimiter / CircuitBreaker / LocalCache / VerificationCode / Idempotent | 安全 | 内部同步或并发容器 |
| StopWatch / CsvWriter / CsvReader / HttpRequest.Builder | 不安全 | 单线程使用，或外部同步 |
| HttpTool / Webhook 三个实现 / Logging 系列实现 | 安全 | 无状态或仅持有不可变字段 |

### 7.3 异常约定速查

| 异常 | 触发场景 |
|---|---|
| `BizException(code, message)` | Assert 断言失败、业务主动抛出 |
| `IllegalArgumentException` | 工具方法入参非法（长度、范围、空值） |
| `IllegalStateException` | 状态不合法：验证码防刷触发、熔断/计时器误用、可选依赖缺失（QrCodeUtils）、时钟回拨超限 |

| `JwtException` | JWT 签名不符、过期、未生效、格式非法 |
| `DateTimeParseException` | DateUtils.parse 格式不匹配（原样透传） |
